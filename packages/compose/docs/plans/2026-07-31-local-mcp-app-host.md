# Local MCP Apps Host: Delivery Plan

Status: in progress\
Owner: `@mcpview/compose`

## Goal

Make a dashboard generated by `mcp-compose` a functional local MCP Apps host. The first acceptance
target is the existing Casys Digital Thread Console, which must display live observations and retain
its refresh and run-detail interactions without relying on a server-specific `/ui` endpoint.

## Non-goals

- Remote publication, tunnels, OAuth, or multi-tenant access.
- A no-code dashboard builder or agent authoring layer.
- Proxying arbitrary MCP methods or arbitrary tools.
- Changing the Digital Thread console's control-plane ownership.

## Work packages

| Package        | Deliverable                                                              | Acceptance evidence                                                                                                                        |
| -------------- | ------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------ |
| Connection     | Stateless-first and legacy Streamable HTTP clients in the cluster        | `callTool` and `readResource` work against both a `2026-07-28` stateless server and a server that requires initialization/session headers. |
| Renderer       | Per-slot local iframe URL, handshake, result delivery, and request relay | Generated HTML preserves static rendering when no host options are given; interactive HTML only advertises implemented capabilities.       |
| Local host     | `/ui/:slot`, `/api/slots/:slot/mcp`, lifecycle handle                    | App tool calls are bound to the slot's explicit allowlist; shutdown stops the cluster.                                                     |
| Fixture        | Strict MCP resource-only server                                          | `GET /ui` is 404 while `resources/read` provides an MCP App resource and a tool result contains structured data.                           |
| Digital Thread | Explicit console manifest/template and how-to                            | Real Console snapshot, refresh, and run-detail work against the live local service.                                                        |

## Invariants to test

1. A dashboard can never fetch a UI resource by guessing an upstream `/ui` URL.
2. `ui/notifications/tool-result` is sent only after `ui/notifications/initialized`, and carries the
   complete result object.
3. A request from slot 0 cannot call a tool allowed only for slot 1.
4. A tool not marked `appCallable` is rejected even if the underlying MCP exposes it.
5. A child receives JSON-RPC errors, not an unhandled browser exception, when its source MCP fails.
6. Existing `ui/compose/event` sync continues to route only according to declared rules.
7. A temporary stdio child process is terminated when the dashboard handle is shut down.

## Manual proof sequence

1. Start the Digital Thread console on `127.0.0.1:3020` and its Docker services.
2. Start the local Compose host from the console manifest/template.
3. Open its loopback URL.
4. Verify Fleet/Runs show the live state, not the labelled demo fixture.
5. Click **Refresh** and verify the console's own `console_refresh` runs.
6. Open an observed run and verify `console_run_detail` succeeds.
7. Attempt an undeclared tool through the host endpoint and verify it is rejected.
